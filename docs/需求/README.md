> 本文是对本仓库**业务需求**的汇总入口，面向产品理解与换机交接。  
> 详细规格、配置步骤见文末「相关文档」。

## 1. 要解决什么问题

在**线下教室**中，老师电脑本地打开网页，完成两类能力（彼此解耦）：

| 模块 | 一句话需求 | 当前版本 |
|------|------------|----------|
| **视频解析** | 相机看学生横排 → 左到右编号 → 谁举手 / 谁先举手 | **V1.0（已满足）** |
| **语音作答** | 选定题目后听学生口头作答 → 与标准答案比对是否答对 | **V2.0（已满足本轮测试）** |
| **计分板** | 独立页大号显示编号；最先举手持续闪烁；语音答对后该人 +1 并停闪 | **仅展示（跨页总线）** |

**明确不做（本仓库范围外 / 由计分板页单独承接积分）：**

- 完整考务流程系统（选题策略、排行榜持久化、多班管理等）
- 「抢答开始 / 下一轮」与教务系统深度绑定（计分板：答对停闪后可再举手；视觉快版另有「下一轮」）
- 永久人脸底库 / 姓名学号绑定、多机位（本版仅有**当次锁定**的人脸↔座位号会话绑定）
- 云端托管教室（默认本机浏览器 + 本机 Python）

下游若需要计分或流程，应订阅本模块输出的事实信号（如「最先举手 = N」「本题 passed」），自行实现。

## 2. 用户与场景

| 角色 | 诉求 |
|------|------|
| 老师 | 看实时画面与编号；看见谁先举手；听学生口头作答并得到对错反馈 |
| 下游开发者 | 拿到稳定的视觉 / 语音结果，不必嵌入 MediaPipe 或 ASR 细节 |

**场景假设：**

- 教室横排约 1–6 名学生（人数可配置，快版默认调试为 2）
- USB / UVC 相机；老师电脑本机运行
- 题目由外部选定（语音页用下拉 / `question_id`），本模块不负责出题

## 3. 视频解析需求（V1.0）

### 3.1 目标

1. 从本机相机取流并在网页预览。  
2. 检出在场学生，按躯干水平位置 **从左到右** 编号。  
3. 基于姿态（非人脸）判断每人是否举手：**腕明显高于同侧肘**即可（不必过肩）。  
4. 判定 **时间上第一个** 进入举手状态的人，网页上对应编号闪烁 / 高亮。  
5. 支持清空本轮赢家后再赛；支持重新锁定编号（换人或大挪位）。

### 3.2 推荐入口与行为

| 项 | 说明 |
|----|------|
| 页面 | http://localhost:5173/people-fast.html（相机）· http://localhost:5173/people-video.html（本地视频） |
| 启动 | `start-people-fast.bat` / `start-people-video.bat` |
| 流程 | 人数达标并稳定 → **Python 左→右排序一次并锁定** → 之后只做举手与「谁先举手」 |
| 身份 | 锁定时左→右编号，并给人脸建会话模板；丢检后优先**人脸**再按座位位置找回原编号 |

### 3.3 验收要点（V1.0 已对齐）

- [x] 人数达到设定值后锁定编号（可调 1–6）  
- [x] 举手 / 放下可感知；最先举手有反馈  
- [x] 「下一轮」清赢家；「重新编号」可重排  
- [x] 短暂丢检后尽量保持原号（人脸绑座 + 座位槽位）  
- [x] 不内置计分  

对照页（每帧排序）：`people.html` / `start-people.bat`。

### 3.4 计分板（`scoreboard.html` · 仅展示）

与视觉 / 语音**分页独立**；同源标签页通过 `BroadcastChannel`（`classroomBus`）互通。

| 行为 | 说明 |
|------|------|
| 大字编号 | 视觉页锁定后同步座位，显示 `#N` 与积分 |
| 最先举手 | 对应编号 **持续闪烁**（不停） |
| 语音答对 | 该号积分 **+1**，停止闪烁；视觉页点「下一轮」后再赛 |
| 启动 | `start-scoreboard.bat` → 计分板 + 视觉快版 + 语音页 |

## 4. 语音作答需求

### 4.1 共同目标

1. 外部已选定当前题（`question_id`）。  
2. 采集学生口头作答并转成中文文本。  
3. 与答案库中该题**唯一**标准答案匹配；相似度 ≥ **90%** 视为答对。  
4. 返回结构化结果（题目、转写、期望答案、分数、是否通过等）。

### 4.2 V2.0（推荐 · 在线）

| 能力 | 要求 |
|------|------|
| 听写 | 按下开始后 **实时转写**（浏览器 Web Speech，`zh-CN`） |
| 匹配 | 字形 + 拼音同音 + **DeepSeek 整句语义**，取最高分 ≥ 90% |
| 限时 | **10 秒**：通过即停；超时结束并做最终匹配 |
| 答案库 | JSON：`prompt` 题干 + `options` A–D + `answer`；相对路径可切换 |
| 读题 | 选题后扬声器朗读题干与四选项（**不念**标准答案）；可再点「扬声器读题」 |
| 环境 | 需联网；Chrome / Edge；麦克风权限 |

- 页面：http://localhost:5173/speech-online.html  
- 启动：`start-speech-online.bat`  
- 换机配置：[`docs/SETUP-speech-v2.md`](../SETUP-speech-v2.md)

### 4.3 V1.0 路径（离线对照）

- 按下录音 → 上传 → 本机 **faster-whisper** 转写 → rapidfuzz 匹配  
- 页面：http://localhost:5173/speech.html  
- 启动：`start-speech.bat`

## 5. 非功能需求

| 项 | 要求 |
|----|------|
| 运行形态 | 老师电脑本地；现代 Chromium 系浏览器优先 |
| 部署 | 不拷贝 `node_modules` / `.venv`；每机自建环境 |
| 密钥 | DeepSeek Key 等仅存本机 `online.env`，**不进 Git** |
| 模块边界 | 视觉代码在 `src/vision/`；语音在 `python/speech_answer/` 等；计分另模块 |
| 可测性 | 关键点 / 匹配等有单测；实机相机与麦克风需人工验收 |

## 6. 技术方案摘要（实现需求时采用）

便于对照「需求 → 怎么实现的」：

| 需求点 | 技术方案 |
|--------|----------|
| 人体姿态 / 举手 | MediaPipe Pose Landmarker（浏览器） |
| 左→右编号 | 躯干 x 排序；Python FastAPI 排序 API；快版锁定一次 |
| 编号防丢 | 锁定时千问 VL 建会话模板；人在场不再轮询；丢座位后最多每秒补检，优先人脸再位置找回**原号** |
| 谁先举手 | 连续帧防抖 + FirstRaise 上升沿竞态 |
| 离线语音 | faster-whisper + rapidfuzz |
| 在线语音 | Web Speech + pypinyin + DeepSeek 语义 |
| 前后端联通 | Vite + TypeScript；Python FastAPI / Uvicorn `:8765` |

更细的栈说明见仓库根目录 [`README.md`](../../README.md)。
